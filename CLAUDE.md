# Project conventions

Conventions and architecture decisions for this repository. Read this before
changing anything; [README.md](README.md) covers setup and scripts.

---

## Ground rules

1. **Every network call goes through `axiosInstance`.** No bare `axios`, no
   `fetch`, anywhere in `src/`.
2. **Every `axiosInstance` call is wrapped in a TanStack Query hook** in
   `src/lib/queries/`. Components never call the client directly.
3. **Tailwind defaults first.** Reach for a custom token only when the brand
   genuinely needs something the defaults cannot express.
4. **Legal and long-form copy is markdown**, never JSX.
5. **Add shadcn components with the CLI, then restyle them.** Never ship one
   looking like boilerplate.
6. **`import.meta.env` is read only in `src/lib/env.ts`.**
7. Use **pnpm**. No `npm`/`yarn` commands, no `package-lock.json`.

## Styling

### Tailwind defaults first

The palette is Tailwind's own. Neutrals are the `neutral` ramp (what shadcn's
"neutral" base resolves to) and the brand accent is Tailwind's `teal` ramp,
aliased to `--color-brand-*` in `src/index.css` so the intent reads at the call
site. Every value carries a comment naming the Tailwind step it came from.

Spacing, type scale, radii, shadows and breakpoints are Tailwind defaults.
Do not introduce a bespoke scale.

A custom token is justified when:

- it is a brand colour the default palette cannot express, or
- it is a semantic surface the design needs in both themes
  (`--surface`, `--heading`, `--season`, `--snow`), or
- it is the brand typeface.

It is **not** justified for one-off spacing, a slightly different grey, or
recreating the old Sass values. If you find yourself writing a hex code, stop.

### Theme tokens

Light and dark values live in `:root` and `.dark` in `src/index.css` and are
exposed to Tailwind through `@theme inline`. Style against the semantic tokens
(`bg-surface`, `text-heading`, `text-muted-foreground`), not the raw ramp, so
both themes follow automatically. `text-brand-*` exists for artwork that needs
a specific step.

Seasonal accents key off `[data-season="…"]` on `<html>`, which the theme
provider sets. Only `--season` changes — the rest of the palette stays put so
the site never looks like a different brand for a month.

### Layout helpers

- `.container-page` — the standard page gutter and max width. Use it instead of
  re-declaring `mx-auto w-[90%] max-w-6xl`.
- `.focus-ring` — focus treatment for interactive elements that are not shadcn
  primitives. shadcn components bring their own.
- `<Section tone="plain" | "surface">` — a full-bleed band with the standard
  vertical rhythm. Alternate tones down a page, and make a page's closing
  `CallToActionBanner` use the same tone as the section above it so the
  background does not change colour at the banner.

### Dark mode

`dark` is a class on `<html>`, set from the theme store. Never gate on
`prefers-color-scheme` in a component — read the store.

## shadcn/ui

`src/components/ui/` holds the **full** registry, installed up front. Unused
components stay; they are the design system for future work.

### Adding one

```bash
pnpm dlx shadcn@latest add <component>
```

Then restyle it. The registry is a starting point, not the finished look.

### Customising one

Edit the file in place and leave a comment saying what changed and why — future
regeneration would otherwise silently undo it. The components already diverging
from the registry are:

| File            | What changed                                                                                           |
| --------------- | ------------------------------------------------------------------------------------------------------ |
| `button.tsx`    | Added `brand`, `brandOutline`, `brandInverse` variants (pill CTAs) and `xl` / `2xl` / `icon-xl` sizes. |
| `input.tsx`     | Taller control, softer resting fill, clearer focus state.                                              |
| `textarea.tsx`  | Matched to `input.tsx`.                                                                                |
| `accordion.tsx` | Card-style items, larger triggers; removed the fixed content height that clipped lazily loaded media.  |
| `sonner.tsx`    | Reads this app's theme store instead of `next-themes`.                                                 |

`src/hooks/use-mobile.ts` was generated by the CLI and rewritten on top of
`useSyncExternalStore`.

### Conventions inside `ui/`

Generated files import `cn` from the `cn` package and use double quotes; that is
fine, leave it. `src/components/ui/**` is excluded from ESLint and Prettier so
regenerating a component does not produce formatting churn — everything else in
`src/` is linted and formatted.

### Use the primitives

Prefer a shadcn primitive over a hand-rolled element: `Button` over `<button>`,
`Sheet` for the mobile nav, `Dialog` for the lightbox, `Accordion` for the
portfolio categories, `Tooltip` for icon labels, `Badge` for tags, `Skeleton`
for loading states, `Alert` for errors, `sonner` toasts for form feedback.

## Icons

`lucide-react` for everything. The one exception is `src/components/icons/brand-icons.tsx`:
Lucide does not ship third-party logos, so the six social marks are drawn there
in Lucide's own 24×24 / 2px-stroke / round-cap style. Add a new social platform
there and to `SocialPlatform` in `src/types/index.ts`.

`src/components/icons/decorative.tsx` holds artwork inlined from the previous
site so its fills can follow `currentColor`.

## Data fetching

### The client

`src/lib/axios.ts` exports `axiosInstance`. It owns the base URL, the timeout,
the default headers and both interceptors. The request interceptor is where
auth belongs when it is needed. The response interceptor normalises every
failure into an `ApiError` (`src/lib/api-error.ts`), a real `Error` subclass
carrying `status`, `code` and `details`.

Nothing else may import `axios` or call `fetch`.

### Query hooks

One hook per operation in `src/lib/queries/`, cache keys in
`src/lib/queries/keys.ts`.

```ts
export function useSubmitContactForm() {
  return useMutation<ContactSubmissionResponse, ApiError, ContactSubmission>({
    mutationKey: queryKeys.contact.submit,
    mutationFn: submitContactForm,
    retry: false,
  })
}
```

Components consume the hook and render its `isPending` / `isError` states.

Portfolio data currently resolves from a local module rather than the network,
but it is still served through a query hook so the loading and error states in
the UI are real. Moving the catalogue to a CMS means changing the resolver in
`use-projects.ts` and nothing else.

## State management

| Concern                         | Where it lives              |
| ------------------------------- | --------------------------- |
| Server / async data             | TanStack Query              |
| Global client state             | Zustand (`src/store/`)      |
| Component-local state           | `useState` in the component |
| Form state                      | Formik                      |
| Derived cross-cutting behaviour | A hook in `src/hooks/`      |

Three stores, each with one job:

- `theme-store.ts` — light/dark, persisted to `localStorage` under `gp-theme`.
  Also reads and writes the previous site's `mode` key so a returning visitor
  keeps their choice.
- `season-store.ts` — the active season, from `VITE_SEASON_OVERRIDE` or the
  date. `detectSeason()` and `resolveSeason()` are pure and testable.
- `ui-store.ts` — mobile nav open state and the lightbox target.

Subscribe with a selector (`useThemeStore((s) => s.mode)`), never
`useThemeStore()` — the whole-store form re-renders on every change.

Adding a store is a decision worth justifying. Most new state is local.

## Forms

Formik owns field state; Zod owns validation, bridged by
`toFormikValidationSchema` from `zod-formik-adapter`. Schemas live in
`src/lib/schemas/` and their messages are what the visitor reads, so write them
as sentences.

Every field needs a `<Label htmlFor>`, `aria-invalid` when it fails, and an
error node referenced by `aria-describedby` with `role="alert"`. Reserve the
space for that message so the layout does not jump.

Submission goes through a mutation hook. Feedback is a sonner toast.

## Content

| Content                                                 | Lives in                                           |
| ------------------------------------------------------- | -------------------------------------------------- |
| Projects, testimonials, timeline, tech stack, site copy | `src/content/data/*.ts`, typed against `src/types` |
| Privacy policy, terms, uses                             | `src/content/legal/*.md`                           |

Never inline this content into a component. Adding a legal page means adding
the `.md` file, registering it in `src/content/legal/index.ts`, and adding the
route under `MarkdownLayout` in `src/app/routes.tsx` — no new page component.

Markdown is rendered at runtime by `MarkdownContent`, which applies the shared
prose styling and opens external links in a new tab.

## Seasonal branding

Logos live in `public/img/logos/` and are named
`logo-<season>-<black|white>.svg`. `useSeason()` resolves the file name from
the active season and the current theme (dark uses the white variant). Adding a
season means dropping in both variants, extending `Season` in
`src/types/index.ts`, and adding a window to `SEASON_WINDOWS` in
`season-store.ts`.

The Christmas snowfall is a single canvas driven by `requestAnimationFrame`.
Any new ornament goes in `SeasonOverlay`, must be `pointer-events-none` and
`aria-hidden`, must respect `usePrefersReducedMotion()`, and must not add a DOM
node per particle.

## Assets

`public/img/` mirrors the previous site's paths exactly. `_redirects`,
`vercel.json`, `sitemap.xml`, the favicons and the web manifest all point into
it, so **do not reorganise that directory** — the short links and existing
inbound URLs depend on it.

`public/ai.txt`, `llms.txt`, `humans.txt`, `robots.txt` and `sitemap.xml` are
carried over verbatim. Update them when the site's content changes, and keep
the hidden discovery links in the footer and the `<link rel="alternate">` tags
in `index.html` pointing at them.

Portfolio media is served from ImageKit. Always build those URLs with
`imagekitUrl()` / `imagekitSrcSet()` in `src/lib/imagekit.ts`; never hand-write
a transformation string.

Fonts are imported from `src/assets/fonts` in `index.css` so Vite fingerprints
them.

## Components

Pages in `src/pages/` stay thin — they set page metadata with `usePageMeta()`
and compose sections. Markup belongs in `src/components/sections/`, grouped by
the page it serves, with anything reused in `sections/shared/`.

Prefer prop-driven components over duplicated markup. A repeated card, list item
or grid entry should be one component.

Every component is fully typed. `any` needs a comment justifying it, and
`@typescript-eslint/no-explicit-any` is an error.

---

## Accessibility

Non-negotiable, and enforced by `eslint-plugin-jsx-a11y`:

- Semantic landmarks; one `<h1>` per page and headings in order.
- Sections labelled with `aria-labelledby` pointing at their heading.
- Every interactive element is keyboard reachable with a visible focus ring.
- Icon-only controls carry an accessible name.
- Decorative images use `alt=""` and `aria-hidden`.
- Animation respects `prefers-reduced-motion`.
